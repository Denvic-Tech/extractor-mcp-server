# Расписания проектов

Расписание относится ко всему существующему проекту, включая многострочный.
Пользователь выполнения, тип регламентного задания и параметры аварийных повторов
берутся из общих настроек Экстрактора 1С, раздел «Планировщик». В API нет параметра
для выбора другого пользователя. Включение расписания может запустить выгрузку.

## Вызовы MCP

1. Найдите имя в `list_projects`, получите UUID из `verify_project.projectRef`.
2. Прочитайте `get_project_schedule(project_guid)`.
3. Вызовите `preview_project_schedule(change)` и покажите пользователю текущее
   и желаемое состояние, часовой контекст 1С, пользователя выполнения, момент
   активации и известные блокировки.
4. После подтверждения вызовите `set_project_schedule(plan_id, operation_id)`
   с выданным `planId` и новым UUID операции. Payload хранится в плане.
5. Перечитайте `get_project_schedule` и проверьте фактическое состояние.

Пример `change`:

```json
{
  "projectGuid": "4eac24a8-18ba-4ad0-a595-2dba2017bf14",
  "enabled": true,
  "schedule": {"kind": "daily", "time": "08:30:00"}
}
```

| Режим | Значение `schedule` |
|---|---|
| Ежедневно | `{"kind":"daily","time":"08:30:00"}` |
| Дни недели | `{"kind":"weekly","time":"08:30:00","weekdays":[1,3,5]}` |
| Интервал в окне суток | `{"kind":"interval","intervalMinutes":15,"startTime":"09:00:00","endTime":"18:00:00"}` |

Дни недели: 1 — понедельник, 7 — воскресенье. Интервал — целое число от 1 до 1440
минут. Время — `HH:MM:SS`; начало окна строго раньше конца в пределах одних суток.
Время относится к планировщику 1С, а не к часовому поясу MCP-клиента. Ответ содержит
время и часовые пояса сервера, сеанса и информационной базы; в модели сервиса
контекст планировщика дополнительно подтверждает администратор.

Для паузы передайте `enabled:false` без `schedule` или с `schedule:null`.
Для включения с сохранением настроек — `enabled:true`, `schedule:null`.
Создание нового задания требует явного расписания. `disabled` в строке проекта
не управляет регламентным заданием. Пауза не останавливает уже запущенную выгрузку.

## Реализация и защита записи

Период в днях, фильтр дней недели и интервал в секундах заполняются по
[описанию расписаний 1С](https://its.1c.ru/db/content/metod8dev/src/developers/platform/metod/scheduled%20jobs/i8101593.htm).

Фиксированные POST-маршруты: `projects/schedule/get`, `projects/schedule/preview`,
`projects/schedule/set`. Прямой `set` принимает поля preview и строковый
`expectedScheduleState`. MCP предоставляет только применение сохранённого плана
с действием `schedule`; планы создания и изменения проекта с ним несовместимы.

Preview не изменяет задание и не проверяет лицензию. Запись повторяет принятую
политику лицензирования: штатная лицензия и `dateDue >= ТекущаяДата()`.
Сохраняются ограничения доступа к проекту и штатные права редактирования заданий.
Изменение выполняет `Справочники.Экс_Проекты.ИзменитьРегламентноеЗаданиеВыгрузки`.
После записи API перечитывает задание, затем клиент выполняет независимое чтение.

`expectedScheduleState` обнаруживает изменения после preview. Блокировка по связи
проекта с заданием сериализует записи через API. Штатная форма и администратор
планировщика не используют эту блокировку: атомарность сравнения и записи с ними
не гарантируется. Исключите одновременное редактирование этих настроек. Запись
планировщика может выходить за транзакцию информационной базы; ошибка после
вызова штатного метода не доказывает отсутствие изменений.

Если идентификатор сохранён, а задание удалено, API показывает `staleJobId` и
отклоняет изменение. Сначала восстановите связь штатными средствами Экстрактора.
Автоматическое пересоздание могло бы скрыть конкурентное удаление задания.

Результат различает `enabled` и `runAllowedByKnownChecks`. Известные причины:
запрет регламентных заданий в Экстракторе, несовпадение базы выполнения, запрет
внешних ресурсов, уже выполняющийся проект, устаревшая связь. Разрешение по этим
проверкам не гарантирует запуск: блокировка кластера и доступность планировщика
могут потребовать проверки администратором. Фактический запуск подтверждается
журналом и результатом выгрузки, а не флагом активности расписания.

## Повтор и обновление

SQLite автоматически мигрирует ограничения действий, сохраняя старые планы,
использованные идентификаторы и результаты. Завершённая операция возвращает
сохранённый результат без нового запроса записи в 1С. Подтверждённый отказ лицензии
получает статус `rejected`; после устранения причины нужен новый preview.

При обрыве связи операция остаётся `indeterminate`. Вызовите
`get_operation_status` и `get_project_schedule`. Не повторяйте запись с новым
идентификатором до выяснения фактического состояния. Повтор с прежним
идентификатором также не вызывает запись для неопределённой операции.

Для использования обновите расширение API из
Экстрактора 1С начиная с 3.16.1.xx из коммерческой поставки [«Экстрактор данных 1С в BI»](https://bi.denvic.ru/) (EPA_Projects 3.2.0) и перезапустите обновлённый MCP-сервер.
Обновление Python само по себе не добавляет маршруты в работающую 1С.

## Приёмка в тестовой базе

Локально проверены 169 автотестов, оба поставляемых навыка, HTTP-метаданные
(10 проверок) и расширение (13 проверок). После последних уточнений BSL повторно
прошли 34 профильных теста. BSL Language Server не смог проверить файл из-за
незарегистрированной рабочей области; MCP проверки логики и стиля недоступны.
Расширение в рамках этой задачи в живую базу не загружалось.

Автотесты Python и проверки исходников не заменяют выполнение на платформе 1С.
После загрузки расширения проверьте на согласованном тестовом проекте:

1. Чтение без задания и preview всех трёх режимов без записи.
2. Создание выключенного задания, изменение, включение и паузу с сохранением
   расписания. Сверьте пользователя с общими настройками и фактическим заданием.
3. Два preview одного состояния: после применения первого второй должен
   отклоняться. Повтор завершённого `operationId` не должен создавать задание.
4. Потерю ответа после записи: статус операции и чтение фактического задания,
   без автоматического повторения.
5. Удалённое задание с сохранившейся связью, недостаточные права, лицензионный
   отказ и каждую доступную общую блокировку запуска.
6. Один фактический запуск по времени на тестовом проекте; подтвердите журнал,
   пользователя выполнения и результат выгрузки. После проверки приостановите
   тестовое расписание.
