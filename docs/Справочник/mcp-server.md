# Развёртывание MCP 3.3.0

Сервер и методы EPA_Projects используют API 3.3.0. Базовый релиз Экстрактора — 3.16.2.1013; новые методы требуют соответствующих обновлённых модулей 1С. Фактическую версию методов и capabilities проверяй через `readiness`: обновление Python-сервера не обновляет базу 1С. Версия платформы 1С — отдельная характеристика. Совместимость встраиваемых методов с платформой 8.3.5 и режимом 8.2 должна проверяться отдельно от установки расширения: доступность расширений зависит от платформы.

Заказчик выбирает транспорт `EXTRACTOR_PROJECTS_TRANSPORT`:

- `direct_http`: MCP → HTTP-публикации Экстрактора 1С. Несколько баз перечисляются в YAML, их учётные данные хранит сервер. Выбранный `base_id` передаётся во все операции.
- `dcc`: MCP → DCC v2 ← Экстрактор 1С. MCP получает доступные базы из DCC; учитываются коннекторы с `client_contract=extractor-1c/2.0` и командой `mcp` в `supported_commands`. Недоступная сейчас база остаётся в списке. Экстрактор сам опрашивает очередь DCC, исполняет фиксированные команды и отправляет структурированный результат. В этом маршруте MCP не обращается к HTTP-публикации 1С.

У обоих маршрутов одинаковый прикладной контракт, preview/planId и operationId. Выполнение и итог операции различаются: `completed` операции не доказывает `succeeded` выгрузки. Для DCC требуется реализованный серверный контракт команд и результатов; один статус задачи не заменяет результат.

Исходники MCP: `mcp/src/extractor1c`. Методы 1С сопровождаются в коммерческой поставке [«Экстрактор данных 1С в BI»](https://bi.denvic.ru/) (модуль `EPA_Projects`); адаптер DCC — `Экс_DCCv2_MCP`. Отдельная старая API-выгрузка и BSL-сборка в этом репозитории больше не являются источником поставки.

Перед использованием: `list_bases`, выбор базы, `readiness`, затем чтение подключений и проектов. Читай фактическую версию опубликованной базы, не подставляй локальную 3.3.0. Недоступность DCC-контракта или базы сообщается как ошибка, без смены транспорта.

## Чтение приёмника

`inspect_project_receiver` читает приёмник сохранённой строки проекта. Требуются EPA_Projects 3.3.0+ в major 3 и capability `receiver_inspection`. Передавай `base_id`, `project_guid` и конкретный `project_row_id`, если строк несколько. Доступны `checks=["schema"]` (по умолчанию), `count` и `sample`. Для выборки задай `sample_fields` — от 1 до 64 уникальных сохранённых имён полей — и `sample_limit` от 1 до 100; без `sample` список полей пустой и лимит 0.

Метод берёт подключение и таблицу из проекта, не принимает SQL и переопределения приёмника. Он не создаёт проект, таблицу и не запускает выгрузку. Ответ содержит статус каждой проверки, типы колонок, точное количество строк в строковом формате и явно ограниченную выборку с типами значений и NULL. `sourceEqualityVerified=false`: эти данные не означают автоматическую сверку с источником.

Для прямого HTTP логический маршрут `projects/receiver/inspect` передаётся через существующий `projects/verify` с внутренним признаком `receiverInspection=true`. DCC получает логический маршрут через штатную очередь. Клиент вызывает только MCP-инструмент; автоматического перехода между транспортами нет.
