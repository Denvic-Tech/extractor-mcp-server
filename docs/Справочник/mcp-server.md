# Развёртывание MCP

Версия сервера MCP — **3.3.7**, ожидаемый контракт EPA_Projects — **3.3.5**. Поддерживается Экстрактор 1С начиная с **3.16.1.34**; новые методы требуют соответствующих обновлённых модулей 1С. Фактическую версию методов и capabilities проверяй через `readiness`: обновление Python-сервера не обновляет базу 1С. Версия платформы 1С — отдельная характеристика. Совместимость встраиваемых методов с платформой 8.3.5 и режимом 8.2 должна проверяться отдельно от установки расширения: доступность расширений зависит от платформы.

Заказчик выбирает транспорт `EXTRACTOR_PROJECTS_TRANSPORT`:

- `direct_http`: MCP → HTTP-публикации Экстрактора 1С. Несколько баз перечисляются в YAML, их учётные данные хранит сервер. Выбранный `base_id` передаётся во все операции.
- `dcc`: MCP → DCC v2 ← Экстрактор 1С. Поддерживается DCC начиная с **2.0.2**. MCP получает доступные базы из DCC; учитываются коннекторы с `client_contract=extractor-1c/2.0` и командой `mcp` в `supported_commands`. Недоступная сейчас база остаётся в списке. Экстрактор сам опрашивает очередь DCC, исполняет фиксированные команды и отправляет структурированный результат. В этом маршруте MCP не обращается к HTTP-публикации 1С.

У обоих маршрутов одинаковый прикладной контракт. Для SQL при capability `direct_sql_operations` доступны разрешённые прямые операции с `operation_id`; для Kafka, AMQP и 1С Шины нужен предварительный `preview/planId`. Выполнение и итог операции различаются: `completed` операции не доказывает `succeeded` выгрузки. Для DCC требуется реализованный серверный контракт команд и результатов; один статус задачи не заменяет результат.


Перед использованием: `list_bases`, выбор базы, `readiness`, затем чтение подключений и проектов. Читай фактическую версию опубликованной базы, не подставляй ожидаемую версию EPA 3.3.5 вместо ответа базы. Недоступность DCC-контракта или базы сообщается как ошибка, без смены транспорта.

## Подробности ошибок

При ошибках MCP сохраняет код API и `errorId` в ответах с ошибкой через HTTP и DCC. Обновлённый модуль EPA_Projects дополнительно передаёт очищенный текст `errorDetails`, включающий место возникновения ошибки. Максимум — 4000 символов; `errorDetailsRedacted` и `errorDetailsTruncated` показывают скрытие и усечение. Текст с признаками секретов, параметров подключения или SQL скрывается целиком до усечения.

Ожидаемый контракт EPA остаётся 3.3.5; прежний модуль может не возвращать подробности. Тогда полный текст ищут в журнале 1С по `errorId`. Перед повтором записи проверьте исходную операцию, проект и приёмник: наличие ошибки не подтверждает отсутствие изменений.

Проверяй `readiness.mcpVersion`, `expectedOneCMethodsVersion` и фактическую `oneCMethodsVersion` отдельно. Возможность переименования и включения сохранённых полей требует capability `field_mapping`, даже при неизменной версии EPA 3.3.1.

## Чтение приёмника

`inspect_project_receiver` читает приёмник сохранённой строки проекта. Требуются EPA_Projects 3.3.0+ в major 3 и capability `receiver_inspection`. Передавай `base_id`, `project_guid` и конкретный `project_row_id`, если строк несколько. Доступны `checks=["schema"]` (по умолчанию), `count` и `sample`. Для выборки задай `sample_fields` — от 1 до 64 уникальных сохранённых имён полей — и `sample_limit` от 1 до 100; без `sample` список полей пустой и лимит 0.

Метод берёт подключение и таблицу из проекта, не принимает SQL и переопределения приёмника. Он не создаёт проект, таблицу и не запускает выгрузку. Ответ содержит статус каждой проверки, типы колонок, точное количество строк в строковом формате и явно ограниченную выборку с типами значений и NULL. `sourceEqualityVerified=false`: эти данные не означают автоматическую сверку с источником.

Для прямого HTTP логический маршрут `projects/receiver/inspect` передаётся через существующий `projects/verify` с внутренним признаком `receiverInspection=true`. DCC получает логический маршрут через штатную очередь. Клиент вызывает только MCP-инструмент; автоматического перехода между транспортами нет. [Пример вызовов и ограничения](../../mcp/skills/extractor1c/references/10-mcp-projects.md).

## Сохранённые поля и английские названия

В MCP 3.3.3 / EPA 3.3.1 capability `field_mapping` разрешает `update_project`
с `projectName`, свежим `expectedState`, `currentTableName` и `fieldChanges`.
Укажите точный `source`, новое SQL-имя в `target` и/или `noExport:false`,
чтобы включить поле. `noExport:true` отключает последующую выгрузку поля,
сохраняя существующую колонку. Изменение сохраняет типы, вычисления и роли
сегментов; заполнение прежних строк требует отдельной повторной выгрузки.

Перед выбором имён определитесь: штатная транслитерация или английские
аналоги по смыслу. Помощник умеет транслитерацию и ручное редактирование
SQL-маппинга; английский перевод подбирает пользователь или ИИ-клиент.
Пример: «Артикул» — `Article`; для названия единицы измерения включается
«ЕдиницаИзмерения», а её GUID сохраняется отдельным полем.
Таблица задаётся через `tableName` при создании; `fieldChanges` меняет поля.
Подробности: [контракт изменения полей](../../mcp/skills/extractor1c/references/10-mcp-projects.md).
