# Установка и настройка MCP-сервера

Инструкция для MCP **3.3.10**. Если сервер уже установлен, начните с раздела
[«Настройка установленного сервера»](#настройка-установленного-сервера).

Команды ниже выполняются из каталога `mcp/` репозитория, если не указано иное.

## Что потребуется

- Экстрактор 1С в BI **3.16.1.34 или новее**, с лицензией и доступом к нужным базам.
- Опубликованные методы Экстрактора с контрактом **EPA_Projects 3.3.5**.
- Python **3.11+** с `pip` и `venv` либо Docker с Compose v2.
- ИИ-клиент с поддержкой MCP.
- Доступ с машины MCP к публикации 1С или к DCC. Для DCC требуется версия **2.0.2+**.

Установщик MCP не устанавливает и не обновляет Экстрактор в базе 1С.
Подготовку Экстрактора выполняют по
[документации продукта](https://docs.denvic.tech/extractor_docs/extractor_docs/).

Одну и ту же базу можно использовать через её web-публикацию и через DCC.
При прямом доступе нужен адрес API вида
`https://1c.example.test/erp/hs/extractor-projects/v1`, а не адрес web-клиента.
При работе через DCC база получает команды исходящим обменом; её web-публикация
для этого не нужна. Для поиска полей через DCC нужен актуальный снимок метаданных.

## Первичная установка

Получите репозиторий:

```text
git clone https://github.com/Denvic-Tech/extractor-mcp-server.git
cd extractor-mcp-server/mcp
```

На Windows запустите установщик:

```powershell
py -3 scripts/install.py
```

На Linux/macOS:

```bash
python3 scripts/install.py
```

Установщик предложит локальный Python или Docker, запросит адрес и учётные
данные подключения и создаст `.env` и `bases.yaml`.
Для локального запуска он может создать `.venv` и установить зависимости.
Для Docker - собрать и запустить контейнер.

Существующие файлы настроек установщик не заменяет.
Чтобы создать только настройки, используйте `--configure-only`.
Для намеренной замены есть `--overwrite`: исходные файлы сохраняются
в `.local-backups/installer-...` в корне репозитория.
При настройке уже работающего сервера обычно достаточно изменить его файлы,
а не запускать установщик повторно.

Пароли вводятся скрыто. Установщик создаёт случайный токен MCP и записывает
его в `.env`, не выводя на экран. Созданный им `bases.yaml` использует
JSON-нотацию; это допустимый YAML.

## Настройка установленного сервера

Основные файлы расположены в каталоге `mcp/`:

| Путь | Назначение |
| --- | --- |
| `.env` | Параметры MCP, доступ ИИ-клиентов и подключение к DCC, если он используется. |
| `bases.yaml` | Имена, адреса и учётные данные баз для прямого доступа к публикациям 1С. |
| `skills/.user-skills/` | Ваши дополнительные навыки для ИИ-помощника. |
| `state/` | Журнал операций, планы и сохраняемые сценарии при стандартном локальном запуске. |

Примеры:
[.env.example](../../mcp/.env.example)
и [bases.example.yaml](../../mcp/bases.example.yaml).

Переменные окружения процесса имеют приоритет над `.env`.
После изменения конфигурации перезапустите локальный сервер.
В Docker примените изменения с пересозданием контейнера:

```text
docker compose -f docker-compose.install.yml up -d --force-recreate
```

Файлы настроек содержат учётные данные. Ограничьте к ним доступ и не добавляйте
их в Git. На Linux/macOS можно установить права `chmod 600 .env bases.yaml`;
на Windows настройте NTFS-права для владельца и учётной записи службы.

### Файл .env

Для прямого доступа к базам:

```dotenv
EXTRACTOR_PROJECTS_TRANSPORT=direct_http
EXTRACTOR_PROJECTS_BASES_FILE=bases.yaml
EXTRACTOR_PROJECTS_DEFAULT_BASE_ID=erp
EXTRACTOR_PROJECTS_MCP_TOKENS=REPLACE_WITH_RANDOM_MCP_TOKEN
EXTRACTOR_PROJECTS_OPERATION_DB=state/operations.sqlite3
```

- `BASES_FILE` указывает на список баз. При относительном пути запускайте
  процесс из `mcp/`; для службы или ИИ-клиента можно задать абсолютный путь.
- `DEFAULT_BASE_ID` задаёт базу по умолчанию. При нескольких базах без неё
  клиент должен явно передавать `base_id`.
- `MCP_TOKENS` содержит токен доступа ИИ-клиента к MCP по HTTP. Это отдельный
  токен, а не пароль базы или DCC. При пустом значении HTTP-вызовы, кроме
  `/health`, не разрешаются. При запуске через `stdio` этот токен не используется.
- `OPERATION_DB` задаёт файл журнала. Относительный путь разрешается от каталога
  установки `mcp/`, независимо от рабочего каталога процесса.

Замените заглушку токена случайным секретом.
Для получения токена используйте Python в своём закрытом терминале:

```text
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

Для подключения к DCC:

```dotenv
EXTRACTOR_PROJECTS_TRANSPORT=dcc
EXTRACTOR_PROJECTS_DCC_URL=https://dcc.example.test
EXTRACTOR_PROJECTS_DCC_USER=REPLACE_WITH_DCC_USER
EXTRACTOR_PROJECTS_DCC_PASSWORD='REPLACE_WITH_DCC_PASSWORD'
EXTRACTOR_PROJECTS_MCP_TOKENS=REPLACE_WITH_RANDOM_MCP_TOKEN
EXTRACTOR_PROJECTS_DCC_WAIT_TIMEOUT=60
EXTRACTOR_PROJECTS_OPERATION_DB=state/operations.sqlite3
```

Укажите корень DCC или адрес с окончанием `/api`; не используйте `/docs`
или `/v2`. Пароль DCC должен быть непустым.
Список доступных баз в этом случае поступает из DCC, а не из `bases.yaml`.
Параметр `TRANSPORT` относится к настройке экземпляра MCP, а не закрепляет
единственный способ доступа за самой базой.

Необязательные параметры:

| Параметр с префиксом `EXTRACTOR_PROJECTS_` | Назначение |
| --- | --- |
| `TIMEOUT` | Тайм-аут одного исходящего запроса, по умолчанию 60 секунд. |
| `DCC_WAIT_TIMEOUT` | Срок ожидания результата задачи DCC, по умолчанию 60 секунд. |
| `DCC_POLL_INTERVAL` | Пауза между опросами результата DCC, по умолчанию 1 секунда. |
| `PLAN_TTL_SECONDS` | Срок действия плана, по умолчанию 900 секунд. |
| `CA_BUNDLE` | PEM-файл доверенных сертификатов для исходящих HTTPS-запросов. |
| `CLIENT_CERT`, `CLIENT_KEY` | Пара файлов для mTLS, задаются вместе. |

В `.env` используйте однострочные значения. Значения с переносами строк
или `${...}` установщик не записывает; передавайте их через окружение процесса
или используемый менеджер секретов.

### Файл bases.yaml

Для каждой прямой публикации добавьте запись:

```yaml
bases:
  - base_id: erp
    name: ERP
    url: https://1c.example.test/erp/hs/extractor-projects/v1
    user: REPLACE_WITH_1C_USER
    password: 'REPLACE_WITH_1C_PASSWORD'
  - base_id: accounting
    name: Бухгалтерия
    url: https://1c.example.test/accounting/hs/extractor-projects/v1
    user: REPLACE_WITH_1C_USER
    password: 'REPLACE_WITH_1C_PASSWORD'
```

`base_id` должен быть уникальным, а `url` - полным адресом API.
Пустой пароль 1С записывается как `password: ''`, а не YAML `null`.
При необходимости у базы можно указать `timeout`, `allow_http_dev`,
`ca_bundle` и пару `client_cert`/`client_key`.

Для эксплуатации используйте HTTPS. `allow_http_dev: true` предназначен
для доверенного тестового окружения и ослабляет проверку TLS.
В Docker пути сертификатов должны существовать внутри контейнера;
при необходимости добавьте подключение файлов только для чтения.

### Пользовательские навыки

Добавляйте собственные инструкции в:

```text
mcp/skills/.user-skills/<имя-навыка>/SKILL.md
```

Например:

```text
mcp/skills/.user-skills/
  company-rules/
    SKILL.md
    references/
      export-rules.md
```

Файлы должны быть в UTF-8. Пример `SKILL.md`:

```markdown
---
name: company-rules
description: Правила подготовки выгрузок в компании.
---

# Правила подготовки выгрузок

Применяй эти правила при настройке проектов выгрузки.
Подробности находятся в references/export-rules.md.
```

MCP показывает навык через `list_skills` с ID
`.user-skills/company-rules`. Содержимое читается через `get_skill`.
Изменения файлов доступны без перезапуска сервера.

В поставляемом Compose-файле каталог с хоста уже подключён к
`/app/mcp/skills/.user-skills` только для чтения.
Редактируйте файлы на хосте и сохраняйте каталог при обновлении.
[Подробности о навыках и настройке своего Compose](user-skills.md).

## Запуск

### Локальный Python

Если установщик не создавал окружение, выполните на Windows:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m extractor1c.mcp_server
```

На Linux/macOS:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e .
.venv/bin/python -m extractor1c.mcp_server
```

Сервер по умолчанию доступен на `http://127.0.0.1:8001/mcp`.
Проверка процесса: `http://127.0.0.1:8001/health`.
Другой адрес и порт задаются параметрами `--host` и `--port`.

Если ИИ-клиент сам запускает MCP через `stdio`, добавьте
`--transport stdio` к аргументам запуска. Отдельная HTTP-служба тогда не нужна.
[Как подключить ИИ-клиент](client-connection.md).

### Docker

Подготовьте `.env` и `bases.yaml`, затем выполните:

```text
docker compose -f docker-compose.install.yml config --quiet
docker compose -f docker-compose.install.yml up -d --build
docker compose -f docker-compose.install.yml ps
```

При работе только через DCC файл для подключения в контейнер всё равно нужен;
если списка прямых баз нет, создайте `bases.yaml` с содержимым `bases: []`.
Не заменяйте им существующий рабочий список баз.

Compose публикует сервер на `127.0.0.1:8001`, сохраняет журнал в постоянном
volume и монтирует настройки баз и пользовательские навыки только для чтения.
На Windows/macOS Docker должен работать с Linux-контейнерами.
Python на хосте для ручного запуска Compose не требуется.

Для удалённого ИИ-клиента настройте HTTPS-прокси и передачу заголовка
`Authorization: Bearer <токен MCP>`. Если используется собственное доменное имя,
задайте `EXTRACTOR_PROJECTS_ALLOWED_HOSTS` в окружении серверного процесса;
в Docker его можно передать через `env_file`.
[Подробнее о подключении клиента](client-connection.md).

## Проверка после запуска

1. Проверьте `/health`: он подтверждает запуск процесса, но не доступ к базам.
2. Подключите ИИ-клиент. Вызовите `list_skills` и прочитайте применимые документы
   через `get_skill`.
3. Вызовите `list_bases` и выберите нужную базу.
4. Выполните `readiness(base_id=...)`. Проверьте версию MCP, фактическую версию
   методов Экстрактора и доступные возможности.
5. Начните с чтения проектов или метаданных. Запись и запуск выгрузки выполняйте
   в согласованном объёме.

Если DCC не успел вернуть результат изменяющей операции, сохраняйте её
`operation_id` и проверяйте `get_operation_status` для той же базы.
Не заменяйте неопределённую операцию новым запуском.
Успешную выгрузку подтверждает статус `succeeded` исходной задачи.

## Обновление и автозапуск

Перед обновлением остановите MCP и сохраните `.env`, `bases.yaml`,
`skills/.user-skills/` и журнал состояния.
При нестандартном `OPERATION_DB` сохраните указанный каталог.
В Docker сохраните постоянный volume целиком.

Получите новую версию репозитория.
Для локального Python повторите установку пакета
интерпретатором из `.venv`: `python -m pip install -e .`, затем запустите сервер.
Для Docker выполните `docker compose -f docker-compose.install.yml up -d --build`.
Не используйте `down -v` при обычном обновлении: эта команда удаляет volume
с сохранённым состоянием.

Для постоянного HTTP-запуска настройте службу ОС с абсолютным путём
к интерпретатору, рабочим каталогом `mcp/`, доступом к настройкам и правом
записи в журнал. Для `stdio` процесс обычно запускает сам ИИ-клиент.
