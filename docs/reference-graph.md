# Граф ссылочных связей 1С

`analyze_reference_graph` заменяет удалённый `analyze_accumulation_register`.
Это несовместимое изменение имени MCP-инструмента; клиентам нужно обновить вызовы.
Анализ читает только `metadata/describe` и `metadata/list`, не создаёт проекты
и не запускает выгрузку.

## Контракт

| Параметр | По умолчанию | Назначение |
|---|---|---|
| `object` | обязательный | Точное имя исходной сущности или табличной части |
| `expand_paths` | `[]` | Относительные пути ссылочных полей, которые нужно раскрыть |
| `max_depth` | `4` | Максимальное число переходов, от 1 до 10 |
| `max_nodes` | `500` | Максимальное число уникальных сущностей, от 1 до 1000 |
| `max_edges` | `2000` | Максимальное число связей с путями, от 1 до 10000 |
| `include_tabular_sections` | `true` | Автоматически обнаруживать и раскрывать табличные части документов |

Головная сущность всегда раскрывается. Ссылочные цели определяются исключительно
по `metadataTargets`; имя поля и представление типа не служат доказательством.
Справочники, документы и планы видов характеристик раскрываются по выбранным путям.
Путь `А.Б` раскрывает `А`, затем `А.Б` и возвращает прямые ссылки последней сущности.
Перечисления остаются конечными узлами. Все альтернативы составного типа сохраняются.

Непериодические регистры сведений раскрываются автоматически, в том числе вложенные.
Периодические регистры, определённые по полю `Период`, остаются видимыми пропущенными
рёбрами: `status: skipped`, `reason: periodic_register`. Их поля дальше не обходятся,
даже если путь указан в `expand_paths`. Они не предлагаются как строки снежинки.
У регистра нет универсального поля `Ссылка`; ключ соединения требует отдельной проверки.

Ключ аналитики может быть обычной ссылкой на справочник. В проверенной ERP поля
справочников ключей доступны через точку, поэтому достаточно раскрыть их пути.
Обратный поиск регистра по совпадающему типу ключа не реализован: это отдельная связь,
которую нельзя вывести из имени `Ключ...` или считать обычной навигацией через точку.

## Результат

- `nodes`: уникальные сущности, их вид, факт раскрытия и `exportCandidate`.
- `edges`: исходная сущность, поле, цель, относительный `path`, глубина, статус и `steps`.
- `steps`: точные типы целей каждого перехода. Различают ветви составных типов,
  у которых одинаковый текст пути. Не передавай неоднозначный путь в описание объекта
  без выбора типа: API 1С не разрешает неоднозначное раскрытие.
- `join`: подсказка полей соединения; для составного типа нужен дискриминатор типа.
  Для регистра возвращается `requiresValidation: true` и неизвестный целевой ключ.
  Это не готовый SQL и не подтверждение фактической кардинальности данных.
- `relation: tabular_section`: отдельная таблица строк документа; соединение по ссылке
  владельца имеет направление один-ко-многим. Не смешивай её зерно с зерном шапки.
- `status: identity` отмечает собственную `Ссылка`, `cycle` останавливает обратный путь.
- `truncated`, `warnings`, `complete` и `unresolvedExpandPaths`: ограничения и полнота
  запрошенного обхода. `complete` не означает раскрытие всей конфигурации.

Метаданные каждой сущности читаются один раз за вызов. Разные роли и пути к одной
сущности сохраняются раздельно. Лимиты ограничивают результат и дальнейший обход;
если они сработали, нельзя сообщать, что найдены все связи.

## Проверенные сценарии

Выручка и себестоимость, четыре ключа аналитики и ссылки номенклатуры:

```json
{
  "object": "РегистрНакопления.ВыручкаИСебестоимостьПродаж",
  "expand_paths": [
    "АналитикаУчетаНоменклатуры.Номенклатура",
    "АналитикаУчетаПоПартнерам",
    "АналитикаУчетаПартий",
    "АналитикаУчетаНаборов"
  ]
}
```

Ожидаются пути `АналитикаУчетаНоменклатуры.Номенклатура.ЕдиницаИзмерения`
к `Справочник.УпаковкиЕдиницыИзмерения` и
`АналитикаУчетаНоменклатуры.Номенклатура.ВидНоменклатуры`
к `Справочник.ВидыНоменклатуры`. Это реальные имена проверенной конфигурации,
а не имена, которые следует переносить на любую другую базу.

Заказ клиента, все обнаруженные табличные части и их прямые ссылки:

```json
{"object": "Документ.ЗаказКлиента", "include_tabular_sections": true}
```

Чтобы раскрыть номенклатуру товаров дальше, добавь `expand_paths: ["Товары.Номенклатура"]`.

## Обновление и постоянные тесты

Для обнаружения табличных частей требуется обновить наше расширение API 1С:
`metadata/list` теперь возвращает также `Документ.<Имя>.<ТабличнаяЧасть>`.
Ядро Экстрактора не меняется. Без обнаруженных частей результат документа содержит
`tabular_sections_unconfirmed`: это может означать старое расширение либо документ
без табличных частей; полнота в таком случае не подтверждается.

Из каталога `mcp` перед изменением/публикацией всегда выполняй:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Постоянные сценарии находятся в `tests/test_reference_graph.py` и включены в обычный
прогон pytest. `tests/fixtures/reference_graph_erp.json` содержит снимок ссылочных
полей реальной ERP от 03.10.2026, без данных документов и учётных данных.
После обновления 1С сняты шапка и все пять табличных частей заказа: `Товары`,
`ЭтапыГрафикаОплаты`, `СкидкиНаценки`, `НачислениеБонусныхБаллов`,
`ДополнительныеРеквизиты`. Тест проверяет точный состав частей и все их ссылки.
Обнаружение частей дополнительно проверяется независимым примером,
а интеграция нового метода - через протокол MCP.
Снимок не заменяет проверку обновлённого расширения на платформе 1С.

Для живой проверки через локальный MCP:

```powershell
$env:PYTHONPATH = "src"
.\.venv\Scripts\python.exe -m scripts.check_reference_graph_live --start-local
```

Скрипт читает настройки `mcp/.env`, поднимает временный сервер на 127.0.0.1:8001,
выполняет readiness и оба сценария через HTTP MCP, сверяет все ссылочные поля
с живым describe_object и останавливает только созданный им процесс.
Для уже работающего локального сервера опусти `--start-local`.
`--use-legacy-auth` явно разрешает использование прежнего Basic-заголовка
из окружения; если 1С отклоняет эти данные, настрой актуальный `.env`.
Секреты не сохраняются. Графы и диагностический журнал находятся в исключённом
из Git каталоге `.local-backups/reference-graph-live`.
