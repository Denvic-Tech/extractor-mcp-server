# Инициализация очереди выгрузки

Штатный HTTP `НачатьВыгрузку` вызывает `ВыгрузитьПроект` и не имеет параметра
для отдельной инициализации. В Экстракторе уже есть другой публичный метод:
`Экс_МодульВыгрузки.ИнициализироватьПроект(Проект, ИдентификаторСтроки, ЗапускатьВФоне, ИдЗадачиЦУМ, Источник)`.
Его вызывает команда инициализации в карточке проекта. Новое API использует
этот метод, без изменений ядра Экстрактора.

## Порядок вызовов

1. Получить `projectRef` существующего проекта через `verify_project`.
2. `preview_project_initialization(project_guid)` создаёт неизменяемый план
   с действием `initialization`. Предпросмотр не выполняет обработчики.
3. Показать пользователю проект, `queueRows` (rowId и число обработчиков),
   `eligibleRowCount`, `initializationHandlerCount`, пользователя выполнения,
   `current` (выгрузка), `currentInitialization`, `blockers` и `activation`.
4. При разрешении пользователя вызвать `initialize_project_queue(plan_id, operation_id)`
   с возвращённым планом и новым UUID операции.
5. Сохранить `taskId` и вызвать `get_project_export_status(project_guid, task_id)`.
   Для созданной инициализации `taskType` будет `initialization`.

Без `task_id` метод статуса по-прежнему читает последнюю **выгрузку**.
Завершение проверять по конкретному `taskId`; не подменять его идентификатором ФЗ
или регламентного задания. Операция MCP `completed` означает сохранённый ответ
на запрос, а не успешную инициализацию.

## Действие и права

Инициализируется весь проект: штатный метод выбирает включённые строки с
`ИспользоватьОчередьВыгрузки` и выполняет включённые обработчики типа
`ПервичнаяИнициализация`, связанные со строкой. Отдельный выбор строки в первом
контракте отсутствует. Нет активных строк очереди или включённых обработчиков -
предпросмотр блокирует запуск (`NO_ENABLED_QUEUE_ROWS`, `NO_INITIALIZATION_HANDLERS`).
Строки без обработчиков видны в плане с `handlerCount: 0`.

Обработчики могут очищать или заново заполнять очередь и выполнять сохранённую
пользовательскую логику. API не навязывает дополнительную очистку, не меняет
настройки проекта и не вызывает выгрузку. Включённое расписание может обработать
подготовленную очередь после завершения инициализации. Успешная инициализация
не гарантирует ненулевую очередь: результат зависит от источников и обработчиков.

Штатное право: изменение `Экс_Проекты` или роль
`Экс_ИнициализацияОчередиПроектов`. Это отдельная роль, не роль выполнения выгрузки.
Пользователь фонового запуска - текущий HTTP-пользователь. Штатные проверки
Экстрактора сохраняются; проверка `dateDue` для записи настроек проекта к этому
вызову не добавляется. Область разрешённого подключения API сохраняется.

## Исходы и защита от повторов

`started` подтверждается перечитыванием связи проекта, задачи и ФЗ.
`already_running` означает выполняющуюся выгрузку, `initializing` - уже идущую
инициализацию, `rejected` - отказ до запуска. Эти ответы не доказывают запуск
новой инициализации.

При невозможности создать ФЗ штатный метод может выполнить инициализацию
синхронно. API возвращает `launchStatus: finished` только после чтения
терминального результата задачи без ФЗ. Поле `status` различает `succeeded`,
`failed`, `cancelled`; `finished` само по себе не означает успех. Длительный
синхронный fallback может закончиться позже HTTP-таймаута.

При неизвестном результате MCP сохраняет `indeterminate`. Незавершённая или
неопределённая операция выгрузки **или** инициализации запрещает оба вида новых
запусков того же проекта в общем постоянном хранилище, включая новые planId и
operationId. Завершённые операции повторно возвращают сохранённый ответ.
Правила администраторской сверки те же, что в [project-export.md](project-export.md).

Перед выполнением проверяются версия проекта, действие плана, видимый состав
очереди, права, запрет ресурсов и текущие задачи. Штатный метод сохраняет свои
блокировки выгрузки/инициализации. Внешней транзакции вокруг него нет;
одновременное редактирование проекта и связанных обработчиков через 1С нужно
исключить. Отдельное изменение самого справочника обработчиков не входит в
токен версии проекта.

## API и публикация

Фиксированные POST JSON-маршруты относительно `/hs/extractor-projects/v1`:

| Маршрут | Поля |
|---|---|
| `projects/initialization/preview` | `projectGuid` |
| `projects/initialization/start` | `projectGuid`, `expectedProjectState` |

Другие поля, код и произвольный адрес не принимаются. Планы выгрузки нельзя
применять методом инициализации и наоборот. Идемпотентность находится в MCP;
прямые вызовы маршрута записи не использовать.

Нужно обновить наше расширение `ExtractorProjectsAPI` и MCP. Ядро Экстрактора
обновлять не требуется. Для живой приёмки после публикации: preview проекта
с обработчиками, разрешённая инициализация, два чтения одного taskId до итога,
повтор того же operationId, проверка очереди штатными средствами. Ошибки
обработчика и синхронный fallback проверять отдельно в тестовой базе.
