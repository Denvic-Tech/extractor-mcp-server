# Типизированный запрос проекта, версия 1

Отдельного YAML-рецепта нет. Запрос JSON проверяется моделью Pydantic;
JSON Schema строится из этой же модели и опубликована в
[`mcp/schemas/project-template-request-v1.schema.json`](../mcp/schemas/project-template-request-v1.schema.json).

Инструменты MCP:

- `get_project_template_schema()` — локальное чтение JSON Schema, без выбора базы.
- `validate_project_template(request)` — проверка структуры и согласованности;
  не читает метаданные, не выдает план и не подтверждает возможность записи.
- `preview_project_template(request, base_id)` — штатный preview выбранной 1С
  через настроенный транспорт, выдающий существующий план создания.
- `create_project(plan_id, operation_id, base_id)` — прежнее применение этого
  плана; `verify_project_summary` подтверждает фактическое состояние проекта.

Источник задается штатным именем объекта, табличной части или виртуальной
таблицы, например `РегистрСведений.КурсыВалют.СрезПоследних` или
`Документ.ЗаказКлиента.Товары`. Существование источника и пригодность полей
проверяются в целевом preview. Массив `segmentation` содержит три Boolean-роли;
пустой массив означает отсутствие группировок. Для Ссылка/По значению требуется
упаковка 1000. `periodicity` задает периодичность виртуальной таблицы
(например, День для Обороты), независимо от функции сегментации.
Не принимаются BSL, SQL, пользовательские обработчики, неизвестная версия
или дополнительные ключи.

```json
{
  "schemaVersion": 1,
  "definition": {
    "object": "Документ.ЗаказКлиента",
    "projectName": "example_customer_order",
    "tableName": "example_customer_order",
    "connectionName": "Подключение целевой базы",
    "segmentation": [
      {"field": "Ссылка", "segment": "По значению", "regular": true,
       "extended": false, "initialization": false}
    ],
    "maxItemsPerBatch": 1000,
    "includeGuids": true,
    "includeMetadataTypes": true,
    "selectedFields": []
  }
}
```

`selectedFields=[]` выбирает штатный набор полей конструктора. Непустой список
содержит имена сопоставления Экстрактора, включая нужные вычисления и параметры,
как в существующем API; фактический состав проверяется в preview.
`connectionName` можно оставить пустым: прежний механизм выбора подключения
должен разрешить его до выдачи плана. Подключение из другой базы не переносится.

JSON Schema не выражает все семантические условия: проверка путей, уникальности
группировок, переименований GUID и согласования имен выполняется моделью.
Метаданные и лицензия проверяются целевой 1С; локальная valid=true этого не доказывает.

Запрос JSON не является data формата Type/Value для load_template. В этой
реализации технические настройки строит существующий конструктор 1С.
Генератор Type/Value из автономного снимка DCC и новые методы выдачи канонического
шаблона не добавлены; они остаются отдельным этапом после API браузера/результатов DCC.
В DCC-транспорте используется прежний фиксированный projects/preview, новые
имена в серверный allowlist не требуются. Ни один инструмент автоматически
не запускает проект и не устанавливает расписание.

Повторная запись после сетевого таймаута запрещена: читать прежний operation_id.
Не переключать транспорт при отказе DCC. Установка в 1С и возможности DCC
проверяются отдельно от Python-тестов.
