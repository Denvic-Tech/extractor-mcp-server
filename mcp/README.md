# MCP Экстрактора 1С 3.3.3

Поддерживаемый релиз Экстрактора 1С — **3.16.2.1018**, версия методов
EPA_Projects — **3.3.1**. После установки проверяйте фактическую версию методов
и capabilities выбранной базы через `readiness`.

Python-проект: `src/extractor1c`; тесты: `tests`; инструкции: `skills/extractor1c`; клиентский навык: `plugins/extractor1c-cloud/skills/extractor1c`.

Подробная [инструкция установки](../README.md) описывает подготовку 1С, публикацию HTTP-сервисов расширений без DCC, Docker на Unix/Windows, локальный Python, `.env`, `bases.yaml` и подключение ИИ-клиента.

Пошаговый установщик из `mcp/` (по умолчанию одна база без DCC): `py -3 scripts/install.py` на Windows или `python3 scripts/install.py` на Unix. Python 3.11+. Существующие настройки сохраняются; `--configure-only` создаёт только конфигурацию.

Ручная установка, все команды из `mcp/`:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
if (-not (Test-Path bases.yaml)) { Copy-Item bases.example.yaml bases.yaml }
# Заполните настройки и MCP-токен перед запуском.
.\.venv\Scripts\extractor1c-mcp.exe
.\.venv\Scripts\python.exe -m pytest -q
```

Существующий `.env` не перезаписывайте. [Транспорт и базы](skills/extractor1c/CONFIG.md), [общая документация](../README.md), [контракт](../docs/Справочник/mcp-server.md). Методы 1С сопровождаются в коммерческой поставке [«Экстрактор данных 1С в BI»](https://bi.denvic.ru/); старой отдельной BSL-сборки здесь больше нет.

[JSON-контракт подготовки проектов](../docs/Справочник/project-template-contract.md):
`get_project_template_schema`, `validate_project_template`, `preview_project_template`.
Сохранение использует прежний `create_project` и его `plan_id/operation_id`.

## Релиз MCP 3.3.3

MCP 3.3.3 сохраняет версию контракта EPA_Projects 3.3.1. Новый вариант
`update_project` с `fieldChanges` переименовывает любые сохранённые поля и
управляет `noExport` без пересборки источника. Для этой возможности требуется
обновлённый модуль EPA с capability `field_mapping`, даже при прежней версии
3.3.1. SQL-колонки меняются штатным драйвером; DDL и запись 1С не атомарны.
Навыки предлагают выбор штатной транслитерации или английских аналогов:
агент подбирает английские названия, помощник формирует источник и маппинг.
Проверяйте версии MCP/EPA раздельно, сохраняйте operation_id и expectedState.

## Релиз 3.3.1

В рабочем навыке перед новым проектом уточняется выбор штатной транслитерации
или английских аналогов. Уже заданный выбор не переспрашивается.
Подробности: [имена и выгрузка полей](skills/extractor1c/references/10-mcp-projects.md#имена-полей-и-признак-выгрузки).

При capability `direct_sql_operations` SQL-проекты создаются, изменяются,
инициализируются и запускаются без отдельного preview через существующие
инструменты. Сохраняются `operation_id`, контроль состояния и диагностика
задачи. Kafka, AMQP и 1С Шина используют режим с preview-планом.

Согласованы версии MCP, облачного плагина и методов EPA_Projects 3.3.1. В релиз включены диагностика выполнения и исправления подготовки сегментации через штатный конструктор Экстрактора. Обновление MCP не обновляет модули 1С: фактическую версию и capabilities проверяйте через `readiness`.

## Релиз 3.3.0

`inspect_project_receiver` читает схему, количество и явно запрошенную ограниченную выборку из приёмника существующей строки проекта. Требуются опубликованные методы EPA 3.3.0 и capability `receiver_inspection`. По умолчанию выполняется только `schema`; выборка требует имён сохранённых полей (до 64) и `sample_limit` от 1 до 100. Подключение и таблицу выбирает EPA из сохранённого проекта; SQL и переопределение приёмника не принимаются. Большие числа и типизированные ячейки возвращаются без преобразования. `sourceEqualityVerified=false`: наблюдение приёмника не означает сверку с источником.

Прямой HTTP использует прежний URL `projects/verify` с внутренним фиксированным признаком `receiverInspection=true`; логический маршрут `projects/receiver/inspect` передаётся в DCC без этого признака. Обычная проверка проекта не изменена. Пример и ограничения: [методы MCP](skills/extractor1c/references/10-mcp-projects.md).

MCP содержит Python-клиент опубликованного HTTP API Экстрактора (версия методов 3.3.1). Исходники, сборка и проверки модулей 1С находятся в репозитории Экстрактора. Устаревший механизм отправки BSL через `/execute` и синхронизация копий модулей удалены. Блокирующие HTTP-вызовы MCP выполняются в рабочих потоках, сохраняя контекст выбранной базы.
