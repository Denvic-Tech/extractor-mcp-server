# Примеры запросов к MCP Экстрактора 1С

Примеры подходят для ИИ-клиента с подключённым MCP Экстрактора. Замените имена
базы, проекта и приёмника своими. Точное имя объекта агент находит в метаданных
выбранной базы. Пример запроса не разрешает дополнительные действия вне его смысла.

## Установка, запуск и подключение

| Запрос пользователя | Действия агента |
|---|---|
| «Настрой MCP для базы ERP. URL публикации: https://1c.example.ru/erp/hs/extractor-projects/v1; пользователь: mcp; base_id: erp» | Уточнить неизвестный маршрут и способ запуска; прочитать инструкции установки текущего MCP через `list_skills` и `get_skill`. Для direct_http настроить `.env` и закрытый `bases.yaml`; для DCC - подключение к DCC. Секреты не помещать в примеры и Git. |
| «Запусти настроенный MCP» | Найти существующую службу, Compose или команду stdio и запустить соответствующим способом. Не создавать второй экземпляр и не считать порт 8001 обязательным. |
| «Останови MCP этой установки» | Остановить конкретную службу или контейнер. Не завершать все процессы Python и соседние MCP. При неоднозначности уточнить установку. |
| «Проверь подключение к базе ERP через MCP» | Получить `list_bases`, выбрать точный `base_id`, вызвать `health` и `readiness`. Различать настройки MCP, доступ к 1С и доступ из 1С к приёмнику. |

Запуск и остановка сервера выполняются средствами его установки; отдельных MCP-методов
для них нет. Не предполагать наличие `mcp-config.yaml`, навыков `mcp-server-setup`
или `mcp-project-creation`: использовать документы и инструменты текущей установки.

## Метаданные, подключения и создание проекта

| Запрос пользователя | Действия агента |
|---|---|
| «Покажи поля справочника Номенклатура в базе ERP» | Найти точное имя через `search_metadata` с `kinds:["Справочник"]`, дочитать страницы по `nextCursor`, затем прочитать `describe_object_fields` с нужными страницами; показать поля и типы. |
| «Покажи подключения к приёмникам» | Вызвать `list_connections` для выбранной базы; показать названия и типы без секретов. |
| «Покажи существующие проекты выгрузки» | Вызвать `list_projects`; для конкретного проекта при необходимости прочитать `verify_project_summary`. |
| «Создай проект выгрузки Номенклатуры в подключение ClickHouse24. Сегментация - по Коду и первым двум буквам Наименования» | Проверить реальное подключение и поля, уточнить только недостающие настройки по `workflow.md`. Использовать массив `segmentation`: «По значению» для Кода и «Первые две буквы» для Наименования, после подтверждения типов, отдельных ролей `regular`, `extended`, `initialization` и размера упаковки `maxItemsPerBatch` для группировки по значению. Не подменять штатную функцию произвольным выражением. |

Для создания прочитать `workflow.md` и инструкции проверки приёмника, опубликованные сервером.
SQL-прямой режим применять только при подтверждённой capability `direct_sql_operations`
и поддержке прямых аргументов инструментами. Для Kafka, AMQP и 1С Шины нужен план.
Если пользователь не ограничил поля, не задавать `selectedFields`: штатный
помощник должен сохранить поля и вычисления группировок. Явный список только
из реквизитов Код/Наименование/Ссылка может исключить параметры сегментов и GUID.
Если отбор нужен, сначала подтвердить имена вычислений по сохранённому проекту
или диагностическому preview; не конструировать их по догадке.
Сохранять выбор пользователя и `base_id` во всей цепочке. Создание проекта не
разрешает автоматически инициализировать очередь, запускать выгрузку или расписание.

## Диагностика и результат

| Запрос пользователя | Действия агента |
|---|---|
| «Проверь статус выгрузки проекта test_Валюты» | Найти проект и его GUID. Для известного запуска передать его `task_id` в `get_project_export_status`; без ID явно назвать ответ статусом последней выгрузки, а не доказательством выполнения конкретного запроса. |
| «Проверь схему приёмника проекта test_Валюты» | Прочитать `verify_project`, передать `projectRef` как `project_guid`; для однострочного проекта оставить `project_row_id` пустым. Для нескольких строк использовать возвращённый API идентификатор выбранной строки, не имя таблицы. Затем вызвать `inspect_project_receiver` с `checks:["schema"]`. Сопоставить фактические колонки с маппингом; не запускать выгрузку и не менять схему. |
| «Покажи несколько строк из приёмника проекта test_Валюты» | Использовать `inspect_project_receiver` с `checks:["sample"]`, явными `sample_fields` из сохранённого маппинга и `sample_limit` по контракту. Не отправлять произвольный SQL. |
| «Что произошло с операцией, которая завершилась таймаутом?» | Читать `get_operation_status` с исходными `operation_id` и `base_id`. Не повторять изменение или запуск с новым ID до выяснения результата. |

Успех запроса запуска не подтверждает успешную выгрузку. Чтение схемы, количества
строк или выборки из приёмника само по себе не доказывает равенства данных источнику.
`typeComparison:"unknown"` не считать подтверждением совпадения типов; учитывать
возвращённые SQL-типы, маппинг и предупреждения. `status:"idle"` без `taskId`
не означает успешного выполнения выгрузки.

## Ответы и метаданные DCC

`list_projects` может вернуть список строк с именами проектов: это не ошибка
и не список объектов с GUID. GUID для следующих вызовов читать из `projectRef`
в `verify_project` или `verify_project_summary`. `list_bases` также может
возвращать один элемент или список - не терять единственную базу.
В DCC поиск и описание полей читают снимок: сохранять `snapshotId`, смотреть
`receivedAt`, `warnings`, `typeKnown` и дочитывать страницы. Доступность снимка
не доказывает текущую доступность исполняющей 1С; для этого нужен `readiness`.

## Поиск инструкций

На запрос «Какие навыки есть у MCP Экстрактора?» вызвать `list_skills`.
Для нужного навыка прочитать `get_skill(skill_id, document="SKILL.md")`, затем
только относящиеся к задаче документы из полученного списка. Не подменять каталог
сервера перечнем локальных папок клиента.
