# Проверки разработки MCP 3.3.4 / EPA 3.3.1

Отчёты и квитанции тестов сохраняй локально в `docs/test-results/YYYY-MM-DD/` по дате Europe/Moscow; внутренние результаты не входят в публичную поставку.

После изменений кода MCP из каталога `mcp/` запускай `.\.venv\Scripts\python.exe -m pytest -q`. Проверяй массив сегментации, обязательные Boolean-роли, путь поля и все разрешённые функции, исключение объектного формата, preview/planId, идемпотентность операции и раздельные версии MCP 3.3.4 / ожидаемого контракта EPA 3.3.1.

Для `inspect_project_receiver` проверяй закрытые аргументы MCP/HTTP/DCC, отказ старой публикации без capability, schema/count/sample, отсутствие записей проекта, сохранение ошибок, NULL, большие числа строкой и ограничения ответа. Живую проверку выполняй через MCP на применённых методах 1С; SQL-клиент её не заменяет.

Проверяй отдельно: несколько HTTP-баз из YAML; выбор base_id и изоляцию планов; обнаружение поддерживающих MCP коннекторов DCC и исключение несовместимых; отсутствие прямых вызовов публикации 1С в DCC-режиме; структурированный результат, отказ, таймаут и повторное чтение результата задачи.

После изменения формирования проектов или выгрузки нужна новая живая проверка на применённой сборке: справочник и его часть, документ и его часть, РН.Обороты, РС.СрезПоследних, ПВХ, перечисление, журнал и субконто. Сначала подтвердить readiness и доступный приёмник. Выполнять записи и запуск только в разрешённой пользователем тестовой базе. Успешное чтение метаданных не подтверждает создание проекта; completed операции не заменяет succeeded выгрузки. Не переиспользовать старую успешную квитанцию как доказательство новой сборки.

BSL проверяется в репозитории Экстрактора. Платформа 8.3.5 и режим совместимости 8.2 требуют проверки компиляции и поведения встроенных методов отдельно; успешные Python-тесты этого не доказывают. Не возвращать удалённую поддержку старых выпусков Экстрактора через тестовые инструкции.

В отчёте указывать версии, конкретный артефакт, выполненные проверки, свежие задачи и ограничения. Недоступные проверки не считать пройденными.

## Сохранённые поля: fieldChanges (MCP 3.3.4 / EPA 3.3.1)

Проверяй закрытые схемы source/target/noExport, сохранение false и пропуска,
запрет null и дополнительных SQL/BSL/connection override, коллизии имён,
отсутствующий source и отключение сегмента. Оба транспорта используют прежний
projects/update, обязательный operation_id и свежий expectedState. Без
field_mapping операция должна отказаться до изменяющего вызова.
В живой базе проверь обычную строку (Артикул → Article), включение и отключение
представления ссылки с сохранением GUID, native-схему, фактическую выгрузку
и выборку новых колонок. Принятый patch не доказывает заполнение прежних данных.
