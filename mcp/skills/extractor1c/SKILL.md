# Экстрактор 1С

При разработке и исправлении MCP или API Экстрактора обязательно читай
[18-development-tests.md](references/18-development-tests.md) и выполняй
указанные проверки до сдачи работы. После изменений кода запускай полный
набор тестов; после изменений формирования или выполнения выгрузки проверяй
все десять реальных тестовых проектов на применённой сборке.

Для дерева связей факта, аналитики счетов и проверки версии методов 1С читай
[17-reference-tree.md](references/17-reference-tree.md). Показывай tree деревом.

Для регистров накопления предпочитай виртуальную таблицу `Обороты`, если
она доступна и соответствует задаче; подробности в references/15-accumulation-registers.md.

Для анализа снежинки любой сущности используй `analyze_reference_graph`.
Граф содержит прямые ссылки и табличные части документов; выбранные ссылочные
пути раскрывай через `expand_paths`. Периодические регистры сведений пропускаются.
Ключи аналитики раскрывай по подтверждённым ссылкам, без догадок по имени.

Клиент вызывает только MCP-инструменты. Сервер использует выбранный прямой HTTP или DCC v2 маршрут; произвольного выполнения кода и шаблонов в этом процессе нет.

Для операций с проектами читай [10-mcp-projects.md](references/10-mcp-projects.md). При подготовке или изменении выгрузки регистра накопления дополнительно читай [15-accumulation-registers.md](references/15-accumulation-registers.md). Для запуска и диагностики читай [CONFIG.md](CONFIG.md), для изменения развёртывания - [20-deployment-architecture.md](references/20-deployment-architecture.md).

Для запросов «поставь на расписание», «запускай каждый день», «каждые N минут», «приостанови» или «возобнови» применяй раздел «Расписание проекта» ниже. Установка расписания уже созданного проекта не требует повторного создания проекта или настройки его строк.

## Транспорт и версия

MCP и EPA_Projects используют 3.2.0; Экстрактор - начиная с 3.16.1.xx. Вызови `list_bases`, выбери `base_id` и передавай его во все операции. В прямом HTTP-режиме базы перечислены в YAML на сервере; в DCC-режиме базы обнаруживаются через DCC, а 1С сама получает команды. DCC-маршрут не обращается к публикации 1С. `segmentation` передаётся массивом группировок с явным `field` и тремя Boolean-ролями; объект с `mode` не используется.

## Создание и изменение состава проекта

Для справочников и документов спроси о выборе сегмента перед preview:
документы - по периоду (День) или по Ссылка; справочники - по первым двум
буквам Наименование/Код или по Ссылка. По Ссылка нужна упаковка по 1000.
Если выбор уже задан, повторно не спрашивай. Читай
[16-catalog-document-segments.md](references/16-catalog-document-segments.md).

Сначала выполни выбор подключения: 0 - настройка в 1С, 1 - автоматически, несколько - выбор пользователя с повторным использованием в диалоге. Читай раздел «Выбор подключения» в [10-mcp-projects.md](references/10-mcp-projects.md).

Для табличной части документа с сегментацией по дате шапки читай раздел
«Табличная часть документа: дата из шапки» в [10-mcp-projects.md](references/10-mcp-projects.md).
Проверь путь `Ссылка.Дата` в сохранённом проекте перед инициализацией и запуском.

1. Проверь `readiness`, затем получи подключения и проекты; метаданные ищи через `search_metadata`.
2. Раскрывай поля через компактный `describe_object_fields`; полный `describe_object` используй только для диагностики.
   Для справочников и документов сначала прочитай метаданные. В `selectedFields` используй имена полей сопоставления Экстрактора, включая необходимые GUID-вычисления и параметр сегмента. Они могут отсутствовать в метаданных; см. раздел «Выбор полей и сегмент» [10-mcp-projects.md](references/10-mcp-projects.md).
3. Перед записью вызови `preview_project` и сохрани выданный `planId`. После предпросмотра не пересобирай определение.
4. После подтверждения пользователя создай новый UUID `operationId` и вызови `create_project` или `update_project` только с `planId` и `operationId`.
5. После записи вызови `verify_project_summary`. При неопределённом результате сначала вызови `get_operation_status` и проверь состояние; не повторяй запись с новым идентификатором.

Перед созданием уточни сегмент партицирования, префикс проекта и отдельный префикс таблиц, если пользователь их не задал. В вопросах называй настройку именно «сегментом партицирования», а не «группировкой». Для регистра накопления с полем `Период` используй сегмент `День`, если пользователь не выбрал иначе. Создание проекта не запускает выгрузку данных.

Во время изменения живого проекта сначала доведи согласованную операцию до проверенного состояния. Не отвлекайся на рефакторинг клиента, сервера или навыка до итогового `verify_project`, если техническая проблема не блокирует продолжение.


## Действия после создания проекта

После создания и успешной проверки проекта выясни решения пользователя:

1. Инициализировать очередь выгрузки? Да / нет.
2. Выполнить проект сейчас? Да / нет.
3. Если запускать: дождаться завершения проекта? Да / нет.
4. Поставить проект на расписание? Да / нет; если да, на какое?

Уже заданные решения и параметры не переспрашивай. Остальные вопросы задай одним сообщением. Порядок выполнения и необходимые параметры расписания описаны в разделе «После создания проекта» [10-mcp-projects.md](references/10-mcp-projects.md).

Вопрос об ожидании задавай только при выбранном запуске и неизвестном режиме ожидания. «Да» - проверять `taskId` до итогового статуса. «Нет» - после подтверждения запуска вернуть `taskId` и доступный `backgroundJobId`, завершить наблюдение без опроса до окончания. Сообщать «запущен», а не «успешно выполнен»; позже статус можно запросить отдельно. Отказ от ожидания не отменяет запуск. Ранее указанное «не жди» или «дождись» не переспрашивать.

## Расписание проекта

После подключения прочитай серверные инструкции через `list_skills` и `get_skill`. Для расписания читай раздел «Расписание» в [10-mcp-projects.md](references/10-mcp-projects.md). Используй `get_project_schedule`, `preview_project_schedule`, затем после подтверждения `set_project_schedule(plan_id, operation_id)` и повторное чтение. Расписание действует на весь проект. Включение может запустить выгрузку; покажи часовой контекст 1С, пользователя выполнения из общих настроек Экстрактора и момент активации из preview. `disabled` у строки не управляет расписанием.

Для запроса «каждый день, раз в час» и примеров стандартного диалога 1С читай раздел «Почасовой повтор и поля диалога 1С» в [10-mcp-projects.md](references/10-mcp-projects.md). Различай интервал повторения, паузу после выполнения и ограничения времени суток.

## Немедленный запуск и проверка выполнения

Для «запусти выгрузку», «выполни проект» и «проверь результат запуска» читай раздел «Запуск проекта» в [10-mcp-projects.md](references/10-mcp-projects.md). Используй `preview_project_export(project_guid)`, затем при разрешении пользователя `start_project_export(plan_id, operation_id)` и `get_project_export_status(project_guid, task_id)` по возвращённому `taskId`.

Запускается весь проект по сохранённым настройкам и очереди. Покажи проект, текущего HTTP-пользователя и немедленную активацию из preview. Существующее явное разрешение на запуск сохраняется; повторно его не запрашивай, если план соответствует разрешённому действию. `completed` операции MCP означает обработку запроса, успешную выгрузку подтверждает только `status: succeeded`. При неопределённости не повторяй запуск с новым планом или ID.

## Инициализация очереди

Для «инициализируй очередь» или «подготовь очередь выгрузки» читай раздел «Инициализация очереди» в [10-mcp-projects.md](references/10-mcp-projects.md). Используй `preview_project_initialization` и `initialize_project_queue`, затем `get_project_export_status` по возвращённому `taskId`. Это отдельное действие: не инициализируй очередь только потому, что пользователь попросил выгрузку.
