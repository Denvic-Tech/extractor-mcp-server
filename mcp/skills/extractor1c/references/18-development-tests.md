# Проверки разработки API 3.2.0

После изменений кода MCP из каталога `mcp/` запускай `.\.venv\Scripts\python.exe -m pytest -q`. Проверяй массив сегментации, обязательные Boolean-роли, путь поля и все разрешённые функции, исключение объектного формата, preview/planId, идемпотентность операции и версию 3.2.0.

Проверяй отдельно: несколько HTTP-баз из YAML; выбор base_id и изоляцию планов; обнаружение поддерживающих MCP коннекторов DCC и исключение несовместимых; отсутствие прямых вызовов публикации 1С в DCC-режиме; структурированный результат, отказ, таймаут и повторное чтение результата задачи.

После изменения формирования проектов или выгрузки нужна новая живая проверка на применённой сборке: справочник и его часть, документ и его часть, РН.Обороты, РС.СрезПоследних, ПВХ, перечисление, журнал и субконто. Сначала подтвердить readiness и доступный приёмник. Выполнять записи и запуск только в разрешённой пользователем тестовой базе. Успешное чтение метаданных не подтверждает создание проекта; completed операции не заменяет succeeded выгрузки. Не переиспользовать старую успешную квитанцию как доказательство новой сборки.

BSL проверяется в репозитории Экстрактора. Платформа 8.3.5 и режим совместимости 8.2 требуют проверки компиляции и поведения встроенных методов отдельно; успешные Python-тесты этого не доказывают. Не возвращать удалённую поддержку старых выпусков Экстрактора через тестовые инструкции.

В отчёте указывать версии, конкретный артефакт, выполненные проверки, свежие задачи и ограничения. Недоступные проверки не считать пройденными.
