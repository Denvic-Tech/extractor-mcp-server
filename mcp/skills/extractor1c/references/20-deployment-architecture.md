# Развёртывание MCP 3.3.1

Сервер и методы EPA_Projects используют API 3.3.1. Версия Экстрактора - начиная с 3.16.1.xx; версия платформы 1С - отдельная характеристика. Совместимость встраиваемых методов с платформой 8.3.5 и режимом 8.2 должна проверяться отдельно от установки расширения: доступность расширений зависит от платформы.

Заказчик выбирает транспорт `EXTRACTOR_PROJECTS_TRANSPORT`:

- `direct_http`: MCP -> HTTP-публикации Экстрактора 1С. Несколько баз перечисляются в YAML, их учётные данные хранит сервер. Выбранный `base_id` передаётся во все операции.
- `dcc`: MCP -> DCC v2 <- Экстрактор 1С. MCP получает доступные базы из DCC; учитываются коннекторы с `client_contract=extractor-1c/2.0` и командой `mcp` в `supported_commands`. Недоступная сейчас база остаётся в списке. Экстрактор сам опрашивает очередь DCC, исполняет фиксированные команды и отправляет структурированный результат. В этом маршруте MCP не обращается к HTTP-публикации 1С.

У обоих маршрутов одинаковый прикладной контракт: прямые SQL-операции при capability `direct_sql_operations`, preview/planId для Kafka, AMQP и 1С Шины, обязательный operationId в обоих режимах. Выполнение и итог операции различаются: `completed` операции не доказывает `succeeded` выгрузки. Для DCC требуется реализованный серверный контракт команд и результатов; один статус задачи не заменяет результат.

Исходники MCP: `mcp/src/extractor1c`. Методы 1С сопровождаются в коммерческой поставке [«Экстрактор данных 1С в BI»](https://bi.denvic.ru/) (модуль `EPA_Projects`); адаптер DCC - `Экс_DCCv2_MCP`. Отдельная старая API-выгрузка и BSL-сборка в этом репозитории больше не являются источником поставки.

Перед использованием: `list_bases`, выбор базы, `readiness`, затем чтение подключений и проектов. Читай фактическую версию опубликованной базы, не подставляй локальную 3.3.1. Недоступность DCC-контракта или базы сообщается как ошибка, без смены транспорта.

Для прямой web-публикации проверь передачу структурированных ошибок 1С:
HTTP-статус, безопасный `code`, `errorId` и, если возвращён штатным guard,
`writeApplied:false` должны доходить до MCP без подмены HTML-страницей.
Если `errorId` есть в журнале 1С, но теряется в MCP, проверь IIS/прокси.
В проверенной публикации Ali проблему устранил `httpErrors
existingResponse="PassThrough"` в location только API
`hs/extractor-projects/v1`. Перед изменением другой установки прочитай её
фактическую конфигурацию; не переключай весь сайт в Detailed и не меняй
аутентификацию. Подтверди результат одной безопасной отрицательной проверкой
через canonical MCP. Ошибка входных параметров preview допустима для этой
диагностики; она не делает preview обязательным для обычного SQL-запуска.
